## 1. 法术分步执行与中途打断

### 1.1 一次 cast 的出手预算：逐步扣，不是整次扣

- 入口 `api.py:6725 _action_cast_instant`。注释仍写着"整次 cast 只扣一次"（`api.py:6728`），**实现已改为逐步**：
  `api.py:6615 _spell_step_payment` 在每次 `StepRequest` 真正开始前调
  `self._consume_action_or_error(actor, action_type="cast")`（`api.py:5370`）。
- 扣点位置：`spell_execution.py:628 _run_action` → 先 `before_step(...)`，只有它返回空才
  调用 `engine._execute_single_daowen_step(...)`。所以**出手扣在目标解析、X 校验、道纹可用性、
  反应窗口、法力支付之前**。
- 单次出手成本不是常数：`_consume_action_or_error` 里 `cost = 1 + action_cost_penalty`
  （`api.py:5393`），即【迟滞】会让法术的**每一步**都 +1 手。
- 最后一步之后的那次让出只是收尾（`spell_execution.py:456` 把状态置 COMPLETED），不再扣手。
- 前置的整批契约校验（句式/步数/X/未持道纹/飞行目标/`trigger_spell_choices` 结构）
  在 `build_instant_execution`（`spells.py:1422`）与 `api.py:6798` 完成，失败时**不扣出手**并回收【黄符】临时道纹。

**由此产生的事实**：`SKIPPED`（目标已失效、`role=attacker` 无对位）与 `DODGED` 的步骤
**同样消耗 1 次出手**，因为扣手发生在其判定之前。代码里没有"跳过退手"的分支。

### 1.2 敌我交替：帧 + 令牌 + 续跑

1. 施法者第一次 `run_to_window()`（`spell_execution.py:469`）推进到第一个 ActionStep 结算完
   并 `yield`，控制权回到 API。
2. 若 `execution.is_running`：`_push_spell_frame`（`api.py:6640`）压帧，帧里记
   `caster_side` / `awaiting_side=对方` / `token`，并把 `state.duel_turn`、`combat_subphase`
   指向对方。
3. 对方行动：行动分发结束后统一走 `api.py:1754 _after_spell_window_action`。
   只有 `priority_action`（真的花了出手，或 skip/rest 或被系统跳过）才会触发续跑；
   `prepare` 这类零出手动作不会推进法术。若对方**新施法压了栈**（栈深变大），本次不恢复外层，
   先处理内层——这是嵌套法术的正确入口。
4. `_resume_spell_stack`（`api.py:6661`）循环：取栈顶 `run_to_window()`；仍在跑就换新 token、
   反手把窗口交给原施法者；若新窗口方在 `combat._ended_turn_sides` 里就 `continue` 自动让过。
   执行结束则弹栈、`_finish_spell_frame` 回收【黄符】临时道纹，再继续恢复外层。
5. `_action_cast_instant` 内部还有一个 while（`api.py:6830`）：如果另一方已经结束回合，
   施法者可以连续推多个空档，不再等对方。

`_spell_window_payload`（`api.py:6627`）只公开 `resolved_steps`（已结算步骤），不泄漏未结算决策。

### 1.4 三种"中途施加"的具体落点（对应提问场景）

- **【唯一】**（`daowen.py:1082`）：效果是给目标挂 `唯一` 状态；
  真正的闸门写在 `DaoWenEngine.resolve` 的统一入口（`daowen.py:1194`）：若施法者身上有【唯一】
  且该道纹名在 `daowen_use_history` 里，直接 `raise ValueError`。
  因为它在第 8 步、`can_use()` 之后、支付之前**抛异常**，被 `spells.py:948` 的 `except Exception`
  当成"道纹计算失败" → `FAILED/INVALID_INPUT` → `ExecutionStatus.FAILED` →
  `api.py:6852` 返回 `{"success": False, "error": "瞬发法术结算失败(no_net_change 之外的 invalid_input)"}`。
  语义上这是一条**正常规则阻断**，却被归入"程序/契约错误"通道（P1-1）。
  另外【唯一】不在 `can_use()` 里，所以 `_eligible_spell_flows`（`spells.py:275`）仍会把该法术列为
  "可用反应"，反应会在结算时才炸。
- **【冰冻】**（`daowen_effect.py:1659`）：施加时立刻把 `target.dao_wen[name].ice_frozen = True`，
  并挂 `冰冻`（`remaining_rounds=-1`）。下一步的 `can_use()`（`models.py:85`）立即返回 False
  → `INTERRUPTED/DAOWEN_UNUSABLE`。战终不自动解除，需 `reconcile_ice` 在状态被移除/转移后重算。
- **【缄默】**：**已不存在的道纹**。`DaWenEngine._registry`（`daowen.py:1103`）里没有"缄默"；
  `daowen_effect.py:1546` 那段 `if name == "缄默"` 是**死代码**（`RELICIZED_DAOWEN_SLOTS` 已把它遗物化）。
  现行等效物是遗物【缄默面具】，判据 `silenced_by_mask`（`spells.py:667`）：
  `state.side_has(actor, "缄默面具")` 且该道纹 `cost_type` 不是"消耗" → 阻塞**持有方自己**。
  它按"己方阵营"判定，所以敌方持有缄默面具**不会**打断你的法术步骤（P2-1）。
- **削减资源**：没有"预扣"概念，法力/碎片在每一步重新读面板；对方在你的 A 步之后用【烁金】/【寒冰法力】等
  把法力或碎片削到不足，则 B 步在第 10/11 步中断。**出手已扣**。

### 1.5 循环与"零净变化"中断

- `_run_loop`（`spell_execution.py:544`）每轮前后取 `battlefield_fingerprint`
  （`spell_execution.py:218`，口径 = 生命/法力/速度/格挡/存活/飞行/离场 + 状态四元组 +
  道纹 `(名, x_value, 冷却, 封印, 冰冻)` + `_BATTLE_COUNTER_FIELDS` 计数）。
- 判定：`本轮可执行步数未增加` 或 `前后指纹相同` → `_stop(INTERRUPTED, NO_NET_CHANGE)`
  （`spell_execution.py:586`）。按用户既定口径，这是**中断**，不是正常结束。
- 读档重放（`_replay_mode`）跳过指纹比对，避免误判。
- 工程保险丝 `MAX_SPELL_LOOP_ITERATIONS=10000` → `LOOP_GUARD`，与规则中断严格分开。
- 指纹字段清单含 `chenglu_paid`、`pending_exhaust_mana`、`deferred_damage`、`shards`、`fake_shards`、
  `total_healed` 等，因此"血炼周天"这类只涨累计量的循环不会在第 1 轮被误判中断。

### 2.2 一次敌对伤害的固定执行顺序（`damage_death.py:595 _apply_hostile_damage_inner`）

1. 逆血龙鳞加值（`hp_lost_this_round`）
2. `apply_multiplier_adjust`（`combat_hooks.py:436`）— 持续状态按 §2.3 排序
3. 【癫狂之脑】×2（仅 `subtype=="attack"`）
4. 【震岳龙躯】封顶 10
5. 【背负】重定向（`apply_redirection`，递归重入本管线，新 ctx 带 `redirected` 标签）
6. `apply_before_damage`（通用 `on_before_damage` 遍历，**当前无实现者**）
7. 【千荆甲】反噬（仅 attack；打死攻击者 → 本次伤害压制为 0，`qianjingjia_suppress`）
8. 贯穿改写 `apply_type`
9. 濒死保护预演：`apply_mitigation`（撤退/负岳碑/断尾求生，`LethalMitigationHook(80, explicit_dispatch)`）
10. 【替死鬼】（玩家将死时把预演落地值转给攻击者，subtype 换成 `tishigui_transfer`，不再触发千荆甲）
11. **受到伤害前** 自动反应（非攻击路径）
12. **失去生命前** 自动反应（非攻击路径）
13. `target.take_damage`：格挡 → `status_adjuster=_commit_incoming_rules`（`apply_incoming_adjust`，§2.3）
    → 失血倍率（【第一杯】）→ 【缓厄沙漏】延期（先挂一半）
14. 【活血衣】/【增生药剂】
15. **受到伤害后** 自动反应（非攻击路径）
16. `_record_hp_loss_event`：**失去生命后** 反应 → 【蚀命刻尺】→ 【承露盏】→ 血翼充能/噬血转换
17. `apply_after_damage_pipeline`（`AfterDamageEffectsHook(90)`：噬伤血囊→噬血→共生血囊→逆鳞→伤痕→寄生→负岳索→龙族血脉斩杀→`_check_hp_zero_death`）
18. 【赦免】检查

注意 6/7 的位置：**千荆甲在格挡与持续状态减伤之前**，反噬量 = 状态调整前的 `amount`（已含癫狂之脑/震岳龙躯修正）。

### 2.3 Hook 排序键（同一窗口内）

- 候选集合：`[h for h in self._hooks if not getattr(h, "explicit_dispatch", False) and hasattr(h, "on_incoming_adjust")]`
  （`combat_hooks.py:459`）。因此背负(70)/濒死(80)/落地效果(90) **不参与**通用遍历，防止双发。
- 排序键 `incoming_key`（`combat_hooks.py:490`）：
  - `mechanism.before_status_rules` → `(-1, priority, name)`（永远最先）
  - 有 `rule_definition` → `rule_definition.ordering_key(status)`
  - 有持续状态 → `(0, X 降序, 施加序, priority)`（`mechanisms/registry.py:149`）
  - 其余 → `(1, priority, 类名)` 或引擎侧 `(2, priority, 类名)`
- 整个窗口在 `copy(resolution_context)` 副本上跑，全部成功才原子提交（trace/执行标记/DEFER 一并回滚）。
- 中间值被压到 0 甚至负数也**不短路**后续规则，窗口结束时负数归一为 0，不产生治疗。
- 非状态 Hook 的 `priority` 仅作后备：千荆甲 40 → 避风铃 50 → 背负 70 → 濒死 80 → 落地效果 90。

### 2.4 反应法术的排序、预算与嵌套

- 触发者内部的**多个候选法术之间的顺序**：`_resolve_spell_reactions`（`spells.py:1123`）直接遍历
  `_eligible_spell_flows(holder, trigger)` 的 dict 顺序 = 内置法术先（`_builtin_spell_flows` 顺序），
  随后是自创法术按 `_ordered_spell_names`。
- `_ordered_trigger_entries`（`spells.py:218`）的"完成序号 `completion_order` → 发现序"排序
  只用于**跨持有者**的两个时点：`目标发动道纹前` 与全局时点。四个伤害/失血时点**不使用**它（P2-2）。
- 自动反应（无交互窗口）的法力预算：`_fire_auto_reaction`（`spells.py:1637`）先取
  `shared_budget = holder.current_mana`，逐个法术用 `_auto_after_life_lost_decision` 预演并从预算里扣
  `_cost`，**同一次失血的多个反应法术共享一份法力**，按声明顺序先到先得。
- 自动反应的 X 选择：`_max_auto_life_lost_x` 从预算往下探到能付得起的最大 X（上限 10000），
  预测走不到的步骤填 `x=1`；预测会走到且 X=1 都付不起时整条法术 `use=False`。
- 自动反应也会做闪避判定（`_auto_reaction_dodge_decision`，走 `ai_rules.choose_dodge`，每回合每人 2 次）。
- **嵌套只允许 1 层**：`_resolve_spell_reactions` 全程持有 `_resolving_life_lost_reactions > 0`
  （名字虽叫 life_lost，实际覆盖四个时点），期间的任何 `_fire_auto_reaction` 直接返回 `[]`。
- 【必中】封锁：`_eligible_spell_flows` 开头 `if self.out_of_turn_blocked(holder): return {}`
  （`spells.py:284`），所以被【必中】锁定的角色连"可选反应"都不出现在 schema 里；
  `_consume_action_or_error`（`api.py:5379`）也拒绝其回合外插队。

### 2.5 【连击 X】逐段还是整次

结论：**5X 段、每段独立结算**。

- 计算：`daowen.py:234 calculate_lianji` → `hits = 5*X`、`damage_per_hit = 1`。
- 结算：`daowen_effect.py:876` 命中 `if name == "连击" or ("hits" in calc and calc.get("damage_per_hit")==1 ...)`，
  循环 `for _ in range(hits)`，**每段单独调用一次 `_apply_hostile_damage(..., 1, subtype="daowen_hit", tags={"daowen","multi_hit"})`**
  （`:897`；波及分支 `:880` 同理，按 `wave_pieces` 平分）。
- 每段因此独立触发：`apply_multiplier_adjust`（逐段读当前值）→ 千荆甲（**不触发**，因为它要求 `subtype=="attack"`，
  而连击段是 `daowen_hit`）→ 濒死保护 → 受到伤害前/失去生命前 → 格挡/状态/失血倍率 → 活血衣 → 受到伤害后 →
  失去生命后 → 承露盏/蚀命刻尺/血翼 → after-damage 管线。
- 循环在 `if not target.is_alive: break` 处提前结束；已打出段数照实记入 `actual_damage` 汇总。
- 因此 1 点/段的碎片化会显著放大"每次失血/每次伤害"类被动（承露盏按 10 点累计，故 5X 段里每 10 段结 1 次账），
  而"每次伤害"类被动（活血衣 = ceil(1/2)=1 点回复/段）会被放大到 5X 次。

## 3. 高危道纹核对

### 3.1 血契 X（`daowen.py:321`、`cost_payment.py:747`）

- **结构**：状态挂在**支付者**身上（`daowen_effect.py:1841`），`value = X`（倍率），
  `source / effect_data.target_id` 指向"额外支付者"，`remaining_rounds = X`。
- **各扣全额，不是平摊**：`_trigger_xueqi_payment` 在自身支付成功后，对目标追收
  `nominal_amount * X`，是**独立的一笔**支付，两者互不冲抵。
- **作用面**：`cost_type in RESOURCE_TYPES` 才回声（`cost_payment.py:717`），即
  `生命/血限/法力/法限/速度/速限/碎片/假碎片`。失忆、异变、冷却、枯竭都**不回声**。
- **资源不足**：`pay_numeric_cost(target, ..., forced=True)` → 跳过足额校验；
  法力 `max(0, before-amount)` 扣到 0；生命走 `_pay_bleed_cost` → `direct_damage`，
  付不起就照扣并 `_check_hp_zero_death`（正常命零）。**没有回滚**，也不退还支付者已付的那笔。
- **能不能让敌方替付失忆/碎片**：碎片能（在 `RESOURCE_TYPES` 内）；失忆不能。
  但要分清方向——血契是"**你付，目标跟着付**"，不是"目标替你付"。
- **级联风险**：`_trigger_xueqi_payment` 内部调用的是**公开** `pay_numeric_cost`，
  `trigger_blood_pact` 用默认值 True（`cost_payment.py:772`）。若目标身上也有【血契】，
  它的回声会继续向外扩散；两端互相持有【血契】时是 A→B→A 的无界递归（无深度闸门）→ `RecursionError`（P1-3）。
- **触发范围比想象大**：血契挂在统一代价总线上，包括遗物自动代价
  （【蚀命刻尺】每次失血强制付血限 1 → 目标也要跟着付血限 X）。

### 3.2 共罪 X（`daowen.py:292`、`cost_payment.py:209/287`）

- **平摊**：`validate_numeric_cost` 在有共罪组时 `parts = _divide_flat(amount, len(pact_group))`。
  ⚠️ 2026-11-02 第三批已改：`_divide_flat` 现为**严格向上取整**（`ceil(M/N)`，不再随机分配余数），
  `_blood_pact_group` 也按 `runtime_id` 去重，每人严格 1 份。
  ⚠️ 2026-11-02 第四批再改：`share_slots = X+1` 的含义是「X 个非自身目标 + 发动者本人」共 X+1 人、**每人各 1 份**，
  不再给发动者额外名额；条文与 `calculate_gongzui` 摘要已同步为「共罪组内每个角色（含发动者）严格各占 1 份名额」。
- 组员拿到的【共罪】状态带同一份 `group_ids`（`daowen_effect.py:1814`），
  所以**任何组员支付时都会触发平摊**，包括作为被选目标的敌方单位。
  也就是说共罪可以做成"敌方也替我分摊碎片"的结构（P2-3，设计上是否允许需裁定）。
- **只分摊资源**：`pact_group` 仅在 `cost_type in RESOURCE_TYPES` 时生效，
  失忆/异变/冷却/枯竭走特殊机制通道，永不平摊。→ **不能让敌方替付失忆**。
- `forced=True` 时跳过足额校验但保留共罪资格与存活校验（`cost_payment.py:319/338`）。
- 与血影的交互：`blood_shadow_cost_share_options` 只在所有承担者付后仍存活时给出候选。

### 3.3 催化 X（`catalysis_steps`）

- 定义：`daowen.py:958`，`cost_type=冷却`、`cost=2X`、`catalysis_count=X`。
- **`catalysis_steps` 的作用**：它是"支付前必须一次性提交的完整预案"。
  `prepare_catalysis`（`daowen_effect.py:185`）在 preflight（`spells.py:760`，**早于催化自身的冷却支付**）里完成：
  - 单持有者：提交恰好 X 项列表；有【波及】时按 `{ref: 有序候选列表}` 提交，每份至少 `ceil(X/人数)` 项，
    实际只执行前 N 项（`_divide_flat` 分配）；
  - 每一项校验：道纹存在且**正在冷却**（`cooldown_remaining` 或 `cooldown_rounds_remaining > 0`）、
    未封印/未冰冻、种类不重复、`x` 为 ≥1 整数且不改变固定 X、目标合法且不越权扩大范围、
    【真理】额外校验陈述句数；
  - 通过后为每个道纹实例写入 `_catalysis_token`，把预案写进 `calc["catalysis_plan"]`。
- **执行**（`execute_catalysis`，`daowen_effect.py:283`）：在催化自身的代价支付完成后执行
  （`daowen_effect.py:1493`），逐个复用 `_execute_single_daowen_step(..., _cooldown_permission=inst)`，
  **不扣额外出手**（直接调用单步核心，绕过 `before_step`）；token 不匹配 → `catalysis_interrupted` 并返回。
  单步中止（非 COMPLETED/DODGED/SKIPPED）也会让整段催化停止。
- 净效果：催化把"冷却中的道纹"变成"立即发动一次"，但被调用道纹仍各自重跑前置、支付自己的代价、
  重新记账冷却与【唯一】历史；固定 X 不被改写；怪物冷却道纹仍受普通 X 上限约束。

### 3.4 出土 X（`daowen.py:938`、`api.py:6311–6345`）

- 效果：给**自己**挂 `出土`（`value = X`、`remaining_rounds = -1`），语义是"接下来 X 次道纹变化保留原道纹"。
- 唯一生效路径是**残韵转换** `_permanently_convert_daowen`（`api.py:6323`）：
  - 新道纹实例以 `dest` 名新建，**复制原实例的 `cost_type/cost_formula/effect_formula` 与 `x_value`**；
  - `dest` 已存在时**不覆盖**；
  - `dest != source` 时：无【出土】→ 删除原道纹（一换一，页数不变）；有【出土】→ 保留原道纹并 `value -= 1`，
    减到 0 移除状态。因此第 X+1 次转换回到"一换一"。
- **承载上限**：`_conversion_capacity_error`（`api.py:6315`）在【出土】生效且 `dest` 为新种类、
  且 `len(dao_wen) >= daowen_capacity` 时**提前拒绝**（残韵不消耗），避免"保留原纹后超页"。
- **不复制的东西**（关键）：`cooldown_remaining`、`cooldown_rounds_remaining`、`is_frozen`、
  `ice_frozen`、`spent_unique` 全部回到默认值。也就是说 **【出土】+ 残韵可以把一个道纹的冷却洗成 0**（P1-4）。
- **与【唯一】的关系**：唯一的判定读 `entity.daowen_use_history`（按**道纹名**记录，
  `models.py:780 mark_daowen_used`），与实例无关。转换后的新名字若历史未被用过就可用，
  原名字仍保持锁定；转换**不会**清除历史，也不会清 `spent_unique`（后者已是死字段，见 P2-4）。
- 出土**不涉及**冷却结算，也不重置已用记录；它只保护"原道纹不被删"和页承载。

### 3.5 分裂 X（`daowen.py:966`、`damage_death.py:1007`）

- **复制了什么：什么都没复制**。`_spawn_fenlie_creations_inner` 每次 `Entity(...)` 新建：
  `blood_limit=current_hp=1`、`mana_limit=current_mana=1`、`speed_limit=current_speed=1`、
  `attack_count=1`、`attack_power=1`，外加 `copy_creator_runtime_id=caster.runtime_id`。
- 因为 `entity_type="造物"`，`models.py:575` 的"非造物自带【透支】"豁免生效 → **新造物没有道纹**；
  也不继承遗物、偏爱、构筑、法术。
- 名字按 `"{caster.name}·造物"`、`·造物2/3…` 递增去重（现场扫描全部参战名单）。
- 阵营：敌方侧施法者 → `state.enemies`；否则 `state.temp_friends`。
- 交出 1 次基础出手（`single_round_action_count` 走 `entity.action_count=1`），共用通用修正。
- 造物立即绑定失血钩子（`_bind_hp_hook`），因此它们的失血同样进总账（承露盏/蚀命刻尺对**造物自身**生效）。

### 3.6 流动 X / 遗忘 X（`daowen_effect.py:416/554`）

- **候选集**：`[s for s in recipient.status_effects if not s.is_expired]` —— **不过滤任何类型**。
  所以 ∞/标记型（强化/弱化/冰冻/波及/共罪）、纯次数型（庇护、篡改、出土、沉溺、操作、必中）、
  镜像型（豪夺）、带控制器指针的（篡改）、带账本指针的（豪夺）全都能被选中。
- 必须显式提交 `status_indices`（`遗忘/流动` X 个不重复整数索引）；候选数恰好等于 X 时可省略，
  否则报错，**不自动降 X**。流动还要求 `flow_target_ref`：另一名存活、可选中、且不等于任何来源目标。
- 结算（`_apply_liudong_yiwang`）搬动的是**同一个 `StatusEffect` 对象**（append 到目标，不深拷贝），
  搬完调 `reconcile_ice` 重算冰冻暂停集合；`_settle_removed_statuses` 做出发地的收尾：
  必中次数归零、无限血限回压、全力/弱化回滚、逆鳞清零、飞行/变形复原。
- **已知的"对象搬家但指针没搬家"（P2-5）**：
  - 【篡改】搬走后 `controller_runtime_id` 仍是原控制者，`source` 仍是原施法者名；
    于是新持有者发动道纹时，会由**原控制者**提交 `tamper` 目标（`resolve_tampered_target` 读的是
    `actor.status_effects` 上的状态），控制关系不随状态迁移。
  - 【豪夺】搬走后，`stolen_relics` 账本仍留在原持有者身上；`_tick_stolen_relics` 在账本所有者身上递减并
    在持有者身上找镜像状态（`_haoduo_status_of`）。镜像被搬走 → 找不到状态也照样到期归还；
    而【回响】对新位置的镜像延长只改 `remaining_rounds`，**改不到账本**，等于续期无效。
  - 【庇护】搬走后按次数生效在新持有者身上（`_shelter_hp_loss` 只看被扣血实体自己的状态），
    这是"效果真的跟着搬"，与【篡改】【豪夺】的"指针不搬"不一致。
- 遗忘：纯粹移除，`_settle_removed_statuses` 走同一套收尾；对【豪夺】= 只删镜像，遗物仍按账本到期归还。

## 4. 缺陷与风险清单

> 本轮只读，**未改任何代码**。分级按"是否会让规则口径出现玩家可见的错误结果"。

**P1-1【唯一】被当成"程序错误"通道**
`DaoWenEngine.resolve`（`daowen.py:1194`）用 `ValueError` 表达"唯一生效中"，而
`_execute_single_daowen_step`（`spells.py:948`）把 resolve 的任何异常都判成 `FAILED/INVALID_INPUT`。
后果：法术中途撞上【唯一】，`execution.status=FAILED`，`_action_cast_instant` 返回
`{"success": False}`（`api.py:6852`），日志把它写成"瞬发法术结算失败"。这是一条正常规则阻断，
应当与 `DAOWEN_UNUSABLE` 同族，走 `INTERRUPTED` 且 `success=True`。
同一通道也吞掉【退化】把 X 降为 0 后的其它非法情形。

**P1-2 没有「速度变化时」法术时点**
`TriggerType`（`spell_execution.py:56`）与 `EXTRA_TRIGGERS`（`spell_dsl.py:82`）里都没有速度类时点。
"速度变化"目前只有三条硬编码遗物路径：回锋刀、避风铃、失速冥灯（`combat.py:580` 起的失速总线）。
玩家无法把"当我失去速度时"写成自创法术；DSL 解析会在学习阶段直接拒绝。

**P1-3【血契】回声可无界递归**
`_trigger_xueqi_payment`（`cost_payment.py:747`）对目标调用公开 `pay_numeric_cost`，
`trigger_blood_pact` 走默认 True。双向【血契】构成 A→B→A 的递归，没有任何深度闸门；
即使不构成环，多次回声也会按 X 的幂级数放大代价。

**P1-4【出土】+ 残韵可洗冷却**
`_permanently_convert_daowen`（`api.py:6323`）新建实例时只复制 `cost_*` 与 `x_value`，
不复制 `cooldown_remaining` / `cooldown_rounds_remaining` / `is_frozen` / `ice_frozen`。
"每场两次冷却"的强力道纹可以被转换成"同代价的新名字"从而立刻再用。
（【唯一】不受影响，因为它按道纹名记历史。）

**P2-1【缄默面具】只惩罚持有方**
`silenced_by_mask`（`spells.py:667`）用 `state.side_has(actor, ...)`，己方持有即封己方的带代价道纹；
对方持有不产生任何影响。若原意是"被施加者无法发动带代价道纹"，方向反了；若原意是"戴着面具者自己失语"，
则目前口径是对的，但缺少规则正文对照说明。另外 `daowen_effect.py:1546` 的【缄默】道纹分支是死代码。

**P2-2 四个伤害/失血时点不按"完成序号"排序**
`_resolve_spell_reactions`（`spells.py:1123`）按 `_eligible_spell_flows` 的 dict 顺序结算，
而 `_ordered_trigger_entries`（`spells.py:218`，按 `completion_order` + 发现序）只用在
`目标发动道纹前` 与全局时点。同一个角色同时有两个"失去生命后"法术时，先发动哪个取决于声明顺序，
不是"先学会的先发动"。

**P2-3【共罪】可以跨阵营分摊**
`_blood_pact_group` 只校验组 id 是否存活，不校验阵营；`共罪` 的目标选择也没有"必须是友方"的约束
（`daowen.py:292`）。因此可以做出"敌方成员被迫分摊我的碎片支付"的结构。

**P2-4 `spent_unique` 是死字段**
`models.py:81` 定义了 `spent_unique`，`custom_resources.py:39` 已注明"仅为旧档遗留"，
全仓库无读取点。它既不影响 `can_use()`，也不影响【唯一】（后者用 `daowen_use_history`）。

**P2-5 流动/遗忘搬走状态实体但不搬指针**

`before_step` 在 `_execute_single_daowen_step` 之前扣手（`spell_execution.py:628`），

**P2-7 `_spell_window_payload` 与战斗日志的"新步骤"口径**
`_resume_spell_stack` 里 `new_steps = execution.step_summaries()[before:]` 用的是
