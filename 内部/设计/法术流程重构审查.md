# 法术流程重构：初步审查与迁移设计

状态：进行中。本文记录已核查的入口与风险，不代表对所有法术、文档、测试的审查已穷尽，也不代表新结构已进入战斗执行。

## 当前实现

- `engine/spell_dsl.py`：文本解析成 ActionStep、IfStep、LoopStep；条件表达式支持逻辑与比较；触发时机词汇表和可用身份分开维护。旧 DSL 必须继续可读，阶数由 `spell_tier` 等遍历旧 AST 计算，分支两臂及触发重数不可丢。
- `engine/spell_execution.py`：`SpellExecution` 的生成器解释嵌套 AST；`_run_if` 即时求值但兼容事件级分支冻结；`_run_loop` 拥有循环次数、已执行数和战场指纹，检查无变化、资源、死亡和单独标识的工程安全阀。步骤调用实际战斗执行，不由 AST 自行改面板。`run_to_window` 在步骤后让出，`run_all` 用于自动反应等。
- `engine/combat_parts/spells.py`：单步预检与道纹结算、触发法术选项、显式和自动反应、全局时点调度；主动施法与事件反应的 `SpellStepPolicy` 不同，反应路径不开新道纹前反应窗口。
- `engine/handlers/daowen.py`、`engine/api.py`：`cast` 分发单纹/定义/瞬发；主动步骤逐次支付并经 `_spell_stack` 在对方行动空档挂起恢复。定义法术和每步支付是不同事项，不可因为接口合并而改变费用。
- `engine/api.py` 的 `_snapshot_spell_stack` / 恢复逻辑记录步骤结果和分支决策，借 `restore_paused` 仅重放控制流，不重复支付或效果。该快照与事务回滚、`engine/sandbox.py` 的副本语义都要覆盖；持久化读档还须逐入口核查，不能把事务快照等同于所有存档能力。
- 回归依据包括 `tests/test_spell_dsl.py`、`tests/test_spell_executor_semantics.py`、`tests/test_spell_priority_windows.py`、`tests/test_spell_loop_mana_gain.py`、`tests/test_reaction_spell_save_roundtrip.py`、`tests/test_spell_tier_by_steps.py` 和法术大全/协力/自动反应等测试；全文检索匹配法术的测试超过百个，仍需逐项核查。

## 已发现的差异和迁移风险

1. `法术索引.md` 将法术循环定义为末尾事件重新触发启动条件；旧 `LoopStep` 由显式标记控制并重复流程，不检查事件是否真实产生。保留旧法术行为和按事件自然循环是两个不同验收目标，不能静默把前者改成后者。
2. `spells.py::_fire_auto_reaction` 使用 `_resolving_life_lost_reactions` 抑制反应自身的反应链，且事件步骤策略不打开新道纹前反应窗口；无条件递归监听会改变既有触发顺序与重入限制。必须设计明确事件队列、所属上下文、完成顺序和抑制范围，并用真实结算测试覆盖。
3. `spell_dsl.py` 可识别的部分触发时机并未实际接线（例如 `规则正文.md` 中的敌回始说明）；不能只校验词汇就声称等待事件可运行。应在事件层基于真实接线校验能力，而不是新建绕过战斗触发的事件总线。
4. 动态求值、事件级冻结以及读档重放有不同语义。简单将全部条件缓存，或全部在恢复时重算，都可能改变旧法术。
5. 用户要求的任意跳转图包含多重/交叉环路。旧的单次循环前后净变化检查依赖明确的循环边界：如何定义任意图的一轮、嵌套/交叉环路的检查点、事件等待跨时段比较，尚未定案；不可把技术步数上限当作规则中断替代。
6. 老的定次循环和 `max_iterations` 有公开行为；兼容迁移必须保留每次执行、计数与中断细节，不能仅将其替换为无条件反向跳转。
7. `get_available_actions` 与束缚入口的限制仍存在不一致；统一入口必须同时核查权限、提示、AI 与调用者兼容，不可只隐藏旧 action。

## 初步中间表示

`engine/spell_program.py` 当前只提供不可变的结构化节点和静态引用检查：道纹动作、条件的真假目标、无条件跳转、等待事件和终止。未指定目标时按节点顺序推进；节点显式 ID 提供稳定跳转，不以固定跳过数量作为唯一控制方式。目标引用验证不验证道纹可用性、事件接线或运行期资源。该结构不处理法术效果，不是新的战斗执行器，也没有接入现有 DSL 或 API。

后续需：旧 AST 降级/迁移至同一 IR，保留动作槽位、阶数、冻结标识、循环计数和检查点；明确程序计数器、事件上下文及可序列化暂停帧；在现有执行器逐步接入统一调度与合法的道纹结算入口；并在真实战斗、存档、回放和完整测试通过后，才移除旧控制流解释。新图在实际执行及事件唤醒尚未实现前不能向玩家宣称可用。

## 已验证与未验证

目前只有结构校验/引用测试及既有 DSL 测试；没有基于新 IR 的真实战斗执行、事件等待、任意循环、中断或读档测试。新结构能否完整表达要求中的运行时语义还没有证明。救赎与凡庸的既有待办也仍未完成。
