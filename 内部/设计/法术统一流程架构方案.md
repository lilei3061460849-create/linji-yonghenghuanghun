# 法术统一流程架构方案（已裁定边界与当前技术状态）

> 本文记录当前有效的规则边界和实现状态。旧稿中关于 SCC、支配关系、交叉环分解、多个重叠循环的优先级等复杂方案，已被后续明确的循环规则取代，不再作为待裁定事项或实现前置条件。

## 1. 已确认的循环规则

1. 一轮流程结束时，再次满足与本次循环入口相同的启动条件，且本轮没有触发中断，即可进入下一轮。
2. 不要求每轮执行相同的步骤或分支。第一轮走 A、第二轮走 B、第三轮走 C，不影响循环成立。
3. 每次回到循环入口，都按当时的真实状态重新判断条件。循环是否继续不取决于分支路径是否相同，也不需要为 A/B/C 分支分别识别循环区域。
4. 任一规则中断发生，立即停止后续循环；已经结算的步骤保留。现行中断规则包括资源不足、步骤未能成功发动、施法者命零，以及单轮前后战场状态无净变化。
5. 自动反应法术是目标身上的事件监听。监听事件触发后，按同一循环和中断规则运行，不设置“最多自动一轮”的额外限制。
6. `max_iterations` 是调用方可选的显式轮数上限，不是自动反应的默认限制，也不覆盖资源、死亡和无进展中断。

循环语义关心的是入口条件、终点是否重新满足该条件，以及期间是否中断；不关心同一轮内部具体走了哪条分支路径。不得把图论算法对循环区域的分类提升为游戏规则。

## 2. 出手费用边界

- 定义自定义法术是主动行动，固定消耗1次主动出手。
- 主动施展法术时，每个实际效果步骤开始前消耗1次主动出手。
- 事件型法术由其触发时机自动发动时，触发时机和自动结算步骤均不消耗持有者主动出手。
- 瞬发法术属于主动施展，按其实际效果步骤逐步支付；事件触发不等同于角色主动释放。

## 3. 当前实现

- `engine/spell_dsl.py`：解析动作、条件分支和显式循环标记。
- `engine/spell_program.py`：将现有 DSL 编译为执行器使用的控制流表示。
- `engine/spell_execution.py`：执行器逐步执行动作；条件在到达时按当前状态求值；循环每轮重新进入流程；记录步骤结果、轮次和分支轨迹；资源不足、步骤失败、零进展和工程安全阀分别处理。
- `engine/combat_parts/spells.py`：主动施法、事件触发、自动反应共用单步结算核心。主动施法通过 `before_step` 逐步支付出手；事件触发路径不绑定主动出手支付回调。自动反应现在不再人为设置单轮上限。
- `engine/api.py`：主动施法的步骤支付、交替行动空档和暂停栈恢复；定义法术的主动行动支付由 `engine/handlers/daowen.py` 负责。
- 测试重点：`tests/test_spell_executor_semantics.py`、`tests/test_spell_loop_mana_gain.py`、`tests/test_spell_priority_windows.py`、`tests/test_reaction_spell_save_roundtrip.py`。

## 4. 不应混淆的工程边界

- 自动反应单轮上限已经取消；反应结算期间对同一反应链的重入抑制仍是独立的调度保护，不等同于限制当前法术只能运行一轮。循环体内部仍可按规则继续多轮。
- `MAX_SPELL_LOOP_ITERATIONS` 是防止程序卡死的工程安全阀，不是游戏规则设定。
- 当前 DSL 的正式循环表达仍是显式循环标记。任意跳转图、事件等待节点尚未作为玩家可用语法接入；不需要为了支持不同分支路径而先完成任意图环路分解。
- 暂停施法的序列化、历史分支轨迹重放及旧存档兼容，属于独立工程验证，不改变上述循环规则。

## 5. 验收要求

- 同一循环连续多轮选择不同分支，按当轮真实状态结算。
- 自动事件反应可运行多轮，直到自然满足中断规则；不因“自动反应”身份提前停止。
- 触发型法术自动结算不扣持有者主动出手；定义法术和主动施展仍按对应规则支付。
- 中断时保留已结算步骤；工程安全阀不得伪装成游戏规则。
- 暂停/恢复不得重复支付、效果或回调；分支轨迹必须按实际访问顺序恢复。
