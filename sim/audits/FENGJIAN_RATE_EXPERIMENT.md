# 献锋汇率实验室：实施与问题记录

## 用户裁定
- 目标汇率：牺牲本回合攻击力 1，回复生命 4（1:4）。
- main 当前事实源仍是 1:1；本实验不修改正式规则、事实源或索引。
- 只在单个实验进程中覆写献锋 effect_rate=4，代价倍率保持 1。

## 实验设计
- 真实 GameEngine.execute_action 走开局、战斗开始、回合开始与 use_daowen。
- 同种子分别跑 1:1 和 1:4，默认 8 个配对种子。
- 发动后由 TacticalAI 执行玩家后续行动，再调用真实怪物阶段与 round_end。
- 记录实际治疗、有效攻击力变化、玩家实际伤害、回终恢复和异常。
- 使用固定生命缺口/法力/速度，清除随机遗物，隔离其他初始道纹。

## 已知局限
- 这是受控战斗回合，不是完整多副本轮回，也不是生产 LLM AI 的长期策略评估。
- 为保证发动献锋后仍有攻击，夹具通过真实状态层增加额外行动；不代表默认行动预算。
- 若怪物阶段或回合结束失败，该样本记为异常，不视为完整对局成功。
- 固定靶怪和固定面板不能代表所有队伍、目标选择与战斗长度。

## 问题记录
1. 对话执行环境没有本地仓库 checkout，无法直接运行本地 pytest。改由 GitHub Actions 云端 runner 运行。
2. 当前连接没有 workflow_dispatch 远程触发动作。工作流因此同时监听本实验分支 push，首次提交应自动启动；若没有启动，列为阻塞。
3. 献锋的代价倍率 rate 与效果倍率 effect_rate 是两个独立字段。1:4 应只改 effect_rate，不能把代价误改为4。
4. 献锋攻击力代价由 1 回合状态实现，回终应恢复。脚本逐样本检查，不恢复即记录问题。

## 安全边界
- 独立分支，不改 main。
- 不改 engine/derivatives.py 正式数据或规则正文。
- 不自动合并 PR。
- Actions 只上传 JSON、Markdown、日志和问题清单。

### P-005：首次云端运行的 Python 导入路径缺失（已定位）

- 现象：Actions 日志报错 ModuleNotFoundError: No module named 'engine'。
- 原因：脚本位于 sim/audits，直接执行时 Python 的首要搜索目录是脚本目录，不是仓库根目录。
- 修复：显式把脚本路径向上两级得到的仓库根目录加入 sys.path。
- 状态：已提交修复，待重跑验证。

### P-006：工作流表达式被转义，导致参数和产物名错误（已定位）

- 现象：runs 环境变量带反斜杠，上传 artifact 报文件名包含非法反斜杠。
- 原因：生成 workflow YAML 时把 GitHub Actions 的表达式转义符也写进了文件。
- 修复：移除多余反斜杠，并在执行命令中启用 pipefail，避免 Python 失败被 tee 的成功状态掩盖。
- 状态：已提交修复，待重跑验证。

### P-007：重复处理开局遗物发现（已定位）

- 现象：每个样本报错“当前没有待选择的遗物发现”。
- 原因：finish_initial_daowen() 内部已调用 resolve_opening_relic() 完成开局遗物选择；实验脚本随后又按 setup_choose_region 返回的历史候选列表重复提交选择。
- 修复：移除第二次 choose_discovered_relic，沿用开局 helper 已完成的真实选择。
- 状态：已提交修复，待重跑验证。

### P-008：玩家与敌方行动必须交替（已定位）

- 现象：第一次实跑中，献锋成功后 TacticalAI 立即尝试继续行动，因优先权已交给敌方而返回空动作；随后脚本强行进入怪物阶段，回合结束仍停在 player_actions。
- 根因：战斗规则要求同一侧两次主动行动之间必须经过对方行动或跳过；额外行动预算不代表可以连续越过优先权。
- 修复：实验驱动器改为按 duel_turn 循环，在玩家行动、真实怪物阶段之间交替；双方出手用尽后才提交 round_end，并检查攻击力是否恢复。
- 状态：已提交修复，待重跑验证。

### P-009：增加“不施放献锋”基准组

- 原 A/B 两组的代价倍率相同（均为本回合攻击力 -1），所以两组实际伤害相同只能说明 1:4 没有比 1:1 多牺牲攻击力，不能量化施放献锋本身相对普攻的机会成本。
- 新增第三臂：同样持有献锋，但本回合不施放，保留完整行动预算与攻击力。
- 三臂同种子配对，分别测出 1:1 与 1:4 相对“不施放”的实际伤害损失。
- 状态：已加入，待云端验证。

### P-010：增加默认行动预算与多行动预算两种场景

- 原三臂对照固定授予2次额外行动（本回合总预算3），可测后续攻击力损失，但不代表普通角色的基础预算。
- 新增基础预算1次（不授予额外行动）与总预算3次（授予2次额外行动）两种场景；每种都跑不施放、1:1、1:4三臂。
- 这样能分开观察：基础预算下施法占掉唯一行动；多行动预算下施法后仍能攻击，但攻击力减益会压低后续每击伤害。
- 状态：已加入，待云端验证。

## 已验证结果（Actions run #11，待新预算分层复跑）

- 8组固定种子，原三臂共24个样本，0异常；所有回合结束成功，献锋攻击力状态均于回终恢复。
- 总行动预算3时：不施放实际伤害276；1:1与1:4均为165。施放献锋的整体机会成本为111实际伤害（包含少一次攻击行动和后续攻击力-1的合并影响）。
- 同场景治疗：1:1实际回复1，1:4实际回复4；两者支付的攻击力代价均为1，输出完全相同。1:4每次多回复3点。
- 因此在这组固定条件下，1:4严格优于1:1；但献锋相对不施放的整体输出机会成本明显，是否值得取决于治疗是否能避免角色死亡/改变战局。
- 以上是单个受控战斗回合，不是完整多回合副本或生产 LLM AI 长期测试。

### P-011：基础行动预算下“没有后续攻击”是预期，不应误报

- 新增预算分层后，基础预算为1时，献锋本身消耗唯一主动行动；该样本没有后续攻击是规则结果，不是 AI 故障。
- 调整异常判定：只在不施放对照组或仍有额外行动预算的施放组中，把零攻击伤害列为异常。
- 状态：已修正，待最终分层实验验证。

## 最终分层实验结果（Actions run #15）

- 运行：48/48 个真实引擎样本，8个固定种子 × 2种行动预算 × 3个实验臂（不施放、1:1、1:4）。
- 16组配对均完整；问题清单0条；全部回合成功进入回终；全部献锋状态在回终恢复攻击力。
- 每组中，1:4 比 1:1 多回复3点生命；攻击力代价同为1；玩家实际攻击伤害完全相同。
- 基础行动预算1：
  - 不施放：实际攻击伤害84。
  - 1:1 / 1:4：献锋消耗唯一主动行动，本回合实际攻击伤害均为0。
  - 相对不施放，施放献锋少造成84点伤害。
- 总行动预算3（基础1 + 2次额外行动）：
  - 不施放：实际攻击伤害276。
  - 1:1 / 1:4：实际攻击伤害均为165。
  - 相对不施放，施放献锋少造成111点伤害。
- 因此当前固定条件下，1:4严格优于1:1：多回复3点，不增加攻击力代价，也没有额外输出损失。
- 但“施放献锋本身”的行动机会成本很大：基础预算时放弃本回合唯一攻击；三行动预算时少造成111点伤害（其中包括少一次攻击行动及攻击力-1对后续命中的影响，未拆成独立因果项）。

## 结论边界

- 这是受控单回合真实引擎战斗，不是完整多回合副本、生产 LLM AI 或多人队伍评估。
- 实验固定玩家生命缺口20点，目标是自己，目标靶怪500生命；不覆盖队友救援、治疗溢出、临界濒死、多个目标和不同战斗长度。
- 这批结果支持“1:4在同样代价下优于1:1”，但不能单独证明1:4的绝对治疗收益足以补偿施法行动的输出机会成本。
- 正式事实源仍保持1:1；没有改规则、没有合并PR。
