# 道纹统一数值规则迁移规范（第一阶段）

> 2026-10-27 校正：【加害】是消耗品施加的状态；【龙鳞】是固定减1遗物，均不再属于 DAOWEN_RULES。旧减法常量仅用于独立规则执行器兼容测试，不参与生产龙鳞结算。


## 1. 当前范围与状态

统一事实源与执行器位于 `engine/rule_engine.py`。当前只迁移共享同一受击伤害阶段的三条规则：

| 道纹 | 稳定规则 ID | 触发运算 |
| --- | --- | --- |
| 加害 | `daowen.jiahai.incoming_damage.add` | `ADD(status.value)` |
| 龙鳞（已转遗物） | `builtins.LONGLIN` | 固定每笔伤害-1，不读旧状态；先于道纹状态链 |
| 固执 | `daowen.guzhi.incoming_damage.cap` | `MIN(constant=1)` |

其余 `DaoWenEngine` 道纹通过 `DaoWenEngine.migration_status(name)` 显示为 `legacy`，继续使用原公式、旧执行路径和既有兼容行为。未迁移原因是本阶段只验证一个完整数值阶段，不是把所有道纹集中搬迁。迁移期间禁止新旧两条实现同时写同一个结算值。

## 2. 新规则定义必须携带的事实

一条可迁移规则必须在唯一 `DaoWenRuleDefinition` / `DamageRuleDefinition` 中声明：

1. 不随文案变化的 `daowen_id`、`rule_id`、名称及对应状态名；
2. `event`、`stage`、目标角色（攻击者/受击者/事件/所有者）；
3. 可组合条件组（ALL/ANY/NOT）；
4. 读取字段、写入字段、读取语义、参数来源及缺失值策略；
5. 运算符、上下界、取整方式、稳定排序后备值；
6. 期限、代价类型/公式，以及由定义生成的可读效果文本。

当前受击链明确要求 `reads=CURRENT_DAMAGE`、`writes=CURRENT_DAMAGE`、`read_semantics=LATEST_VALUE`。规则执行器按既定顺序逐项写回同一个上下文，后项直接读前项更新后的 current，不允许默默回读原始快照。

## 3. 受击阶段契约

当前阶段是：**倍率等上游修正之后，格挡吸收之后，失血倍率之前、扣除生命之前**。

- `original_damage`：CombatEngine 入口值。
- `incoming_damage`：上游倍率修正后、格挡前的值。
- `current_damage`：格挡后进入规则链的当前值；每步 trace 会记录 before/after。
- `post_rule_damage`：规则链完成、失血倍率前的数值。
- `damage_after_life_loss_multiplier`：倍率后待扣数值，兼容旧字段 `actual_damage` 的语义。
- `shield_absorbed`：格挡吸收量。
- `actual_life_loss`：受击前生命值减受击后生命值；过量伤害时可能小于 `actual_damage`。

代价伤害绕过这三个状态规则；普通伤害已被格挡完全吸收时不会调用状态规则。一次正伤害进入规则链后，中间值变为0或负数不短路后续规则；整条链结束后负值钳为0，不能反向治疗。【固执】先在本阶段限制当前受击伤害，并在失血倍率之后执行最终失血封顶，确保非代价受击最终实际失血不超过1点；直接失血路径不经过受击规则。

### 顺序

同一伤害窗口中的道纹状态按 `StatusEffect.ordering_key` 的道纹序列位置排序；缺少序列锚点时，才用静态 `priority`/`rule_id` 作为确定性后备。规则执行器不覆盖当前主线的序列顺序，也不添加「固执+龙鳞」等专属组合表。

## 4. 数值与缺失值政策

伤害边界保持任意精度整数语义，不新增整数位数上限：

- 负整数保持兼容为 no-op，不产生治疗；当前伤害规则链内部可暂存负值，规则窗口结束统一钳为0；
- `None`、布尔值、浮点值、NaN 与正/负 Infinity一律明确抛出规则输入错误；
- `Entity.take_damage` 的失血倍率必须是至少为1的有限整数；
- 状态 `remaining_rounds=-1` 表示期限永久，与伤害数值 Infinity 无关；
- 旧加害/龙鳞状态若缺失 `value`，按显式配置的 0 处理；其它参数缺失默认报错，不能依靠 `or 0` 隐式吞掉。

引擎边界拒绝非有限浮点数，以免它进入状态、事件流或 JSON 输出成为非标准 `Infinity`/`NaN`。独立的 `apply_operator` 接受整数和有理数；若某运算生成非整数伤害，写回伤害上下文时按 `OperatorSpec.rounding` 在唯一写回边界明确取整，并把精确运算与舍入写入 trace。超出运行时 JSON 整数转字符串阈值的 trace 数值表示为十进制字符串，不反向限制伤害输入范围。

## 5. 执行、解释与重入

`CombatHookManager.apply_incoming_adjust` 是当前伤害相位的排序/串行入口；MechanismHookAdapter 只把现有 Hook 调用映射到规则执行器。规则结果写回 `DamageResolutionContext`，并生成稳定、可序列化的 trace（规则 ID、条件树的实测值、阶段、目标、输入字段、读语义、运算符、参数、before/after、执行/跳过原因和解释）。失败规则不得留下执行标记、当前值、延后事件或 trace 的半提交；`CUSTOM` 收到隔离的 `DamageResolutionContext` 副本（保留回调接口）与冻结实体快照，回调对副本容器的修改不会写回真实实体/结算 context。

濒死保护预演和正式扣血是两次独立评估：各自建立 `mode=preview/commit` context，因此同一规则会有两份清楚标记的评估日志，但预演不改实体、不记正式失血、不消费状态。规则 ID 在同一 context 中只能执行一次；重复调用抛出 `DuplicateRuleExecutionError`。`DEFER` 只能登记下一阶段事件，不可在当前链递归分发；复杂效果可使用注册式 `CUSTOM` 运算器，但最终数值、目标和解释仍须回到这个上下文与 trace。

## 6. 兼容与文档同步

- 不改既有道纹 DSL、成本支付、残韵、状态保存格式和未迁移道纹行为。
- `DaoWenEngine.calculate_*` 保留原入口/主要结果键；三个已迁移计算器的 `summary` 读取同一规则定义。
- `max_life_loss_per_hit` 保留为兼容字段，语义是最终实际失血上限；`max_current_damage_per_hit` 表示倍率前受击伤害阶段的上限。两者当前数值均为1，但结算阶段不同。
- 完整封存序列化会保存 `activation_x` 和 `application_sequence`；旧封存档缺字段时按既有默认值恢复。`Entity.to_dict()`/`GameState.to_dict()` 是面板与 API 快照形状，不是 `save_game()` 的完整重建格式；它们暂不承载排序锚点。
- 改规则定义后，更新 `规则正文.md` / 对应副本正文，再运行 `python sim/gen_daowen_index.py` 生成 `全道纹索引.md`；最后运行 `python sim/gen_ai_context.py` 刷新聚合文件，**不要直接编辑 `AI_CONTEXT.md`**。

## 7. 每次迁移的检查清单

1. 只读审计定义、描述、所有实际入口、旧 Hook/内联分支、preview/commit 与状态顺序；用事实列出唯一迁移切点。
2. 明确事件、阶段、角色、原始/当前/最终伤害、实际失血、资源代价与缺省值；找不到来源时先标注风险，不猜。
3. 选定唯一规则 ID 和运算/条件；摘要必须由定义渲染，不在 `calculate_*`、索引或战斗管线另写一份公式。
4. 通过既有入口适配一次；删除/停用旧的同值写入处，增加护栏防止旧分支复活。
5. 测单条规则、混合运算、X/施加顺序、0 中间值、代价/无效输入、preview 与 commit、防重复执行、真实伤害事件与 JSON 安全。
6. 只重生成下游索引/AI_CONTEXT，不手改生成物；报告未迁移项、兼容别名、风险和真实测试结果。

## 8. 当前待跟进风险

- 用户已裁定【固执】采用最终实际失血上限：即使失血倍率生效，非代价受击最终失血也不超过1点。实现由倍率前受击规则与倍率后最终封顶共同保证；直接失血路径仍独立。
- 旧测试曾把 priority 顺序、`raw_damage` 和状态调整后数值混为一谈；新增 trace 将这些字段分开。后续审查测试时应以运行入口和字段定义为准，不照抄历史注释。
- 当前完整存档有排序锚点，但 `Entity.to_dict()` 的 AI/面板快照没有。若未来从这种面板 JSON 还原战斗实体，需升级对应公开快照版本并提供旧字段默认值；本阶段不扩展该接口。
